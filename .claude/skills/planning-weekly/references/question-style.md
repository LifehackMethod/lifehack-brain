# Question style — how planning-weekly asks

> Inherited directly from `planning-daily`'s proven style (2026-06-13, the person: "fucking perfect").
> The shape is the same; the subject is the week, not the day. Applies most in Phase 2 (Connect the Dots)
> and any human-facing round.

## 1. Open with a one-paragraph TL;DR
On the first turn of a phase/step, a single short paragraph: what the Map shows (or what the step surfaced)
+ what it thinks matters. Not the full draft — never dump it ("say 'show me the full map' if you want it").
On later rounds within a step, a one-line framing is enough.

## 2. Then a numbered list of questions — bold lead-ins
Mirror the global `~/.claude/CLAUDE.md` "How to Respond" format: **bold lead-in (the real thing)** — then
a plain-sentence question. Numbered so the person answers by number (he dictates by voice). Weekly questions cover
projects and the week's shape, not daily tasks.

**Cadence:** the person dictates by voice, so batch ~6–8 per round rather than the generic 2–3 — go one-at-a-time
only when the next genuinely depends on this answer. This is the leveraged-question rule in practice: the
minimum number of questions that fill the maximum number of gaps.

## 3. Every question carries a REAL refresher + a best-guess
Assume the person **hasn't looked at this project in a few days.** Give the who/what/when from the actual Map
data — but do NOT dumb down basics. Embed a best-guess so he just confirms/corrects ("Map shows X —
happened, or different?"). No best-guess = it's a knowledge gap, not a question — state the gap.

Example (weekly-shaped):
> **3. Consulting pitch deck** — Map shows it was in progress Wednesday; draft was v1. Did you get to v2
> before EOD Friday, or still at v1? (This matters for triage — it's either ready-to-send or a Must-Deliver.)

## 4. Close with the gate + a suggestion
Every round ends: **"Another round, or move on? — I suggest [X] because [Y]."** The suggestion is the
skill's own read on whether it has the whole picture. Only the person's word advances. A deep question that got a
shallow answer earns a follow-up ("that's not enough — I need more") before advancing.

## Failure modes to AVOID (inherited from planning-daily)
- ❌ One question per lane/project (mechanical). Projects are a silent filter, not the question structure.
- ❌ Zero formatting (a flat list with no lead-ins).
- ❌ Over-formatted emoji surface-headers / heavy sectioning.
- ❌ Dumping the full Map draft.
- ❌ Questions that assume the person has already read the Map.
- ❌ Concluding / recommending instead of asking (see THE LAW in ANCHOR.md).
- ❌ LLM arithmetic on hour-math — compute it, show the expression.
