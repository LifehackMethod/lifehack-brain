# Reconstruction Protocol

Use this when the project doc is created or refreshed after significant work has already happened (a long chat, or legacy brief files).

Do not assume a long or dense source can be reconstructed in one pass. Reconstruct in passes. Each pass may produce notes, then the final pass consolidates them into the project doc.

## Pass 1: Map the arc

Goal: understand the shape of the work.

Extract:
- user goal
- domain/type of work
- major phases
- key entities
- current apparent state
- artifacts/files mentioned
- likely gaps
- whether this is diagnosis, creation, strategy, research, decision-making, coaching, or another mode

Do not finalize yet.

## Pass 2: Extract settled material

Extract:
- confirmed facts
- user constraints
- decisions made
- preferences
- source material
- settings/configuration details
- important quotes or definitions
- "do not do" boundaries

Label confidence.

## Pass 3: Extract actions, tests, and results

Extract:
- actions taken
- experiments run
- revisions made
- tests performed
- observed outcomes
- failed attempts
- what changed after each test
- what each result means

Preserve enough detail to avoid repeating failed paths.

## Pass 4: Extract reasoning state

Extract:
- active hypotheses
- user hypotheses
- AI hypotheses
- competing explanations
- assumptions
- conflicts
- deprecated theories
- uncertainty map
- evidence for/against major interpretations

Do not collapse uncertainty prematurely.

## Pass 5: Reconstruct present state

Answer:
- Where are we now?
- What is active?
- What is the current best model?
- What matters most next?
- What is the user trying to accomplish now?
- What should be held stable?
- What has just changed?
- What is the next useful action?

This section should usually live near the top of the project doc.

## Pass 6: Build future plan

Create:
- next steps
- future experiments/revisions
- decision gates
- open questions
- possible branches
- expert/client/stakeholder questions
- risks
- things to avoid

The plan must follow from what has been learned.

## Pass 7: Consolidate into the project doc

Now produce or update the project doc:
- choose organic structure based on the work
- put current state near the top
- use dense bullets/tables
- preserve exact values and key details
- merge duplicates
- mark deprecated beliefs
- update navigation

## Pass 8: Gap check

Ask:
- Could a new AI continue from this project doc?
- What would still require original chat context?
- Are facts and hypotheses clearly separated?
- Are active next actions clear?
- Are important constraints recorded?

Ask the user for missing context only when it materially blocks the work.
