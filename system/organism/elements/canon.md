### TRIGGERS / MODES

Canon operates in three distinct modes depending on the operation direction.

**1. WRITE (the guarded path) — blocking PreToolUse**

Fires on EVERY `Write` or `Edit` tool call regardless of target. `guard_canon_write.sh` inspects the
`file_path` first; if `/canon/` is not in the path it exits ALLOW immediately (zero cost). If the path IS
a canon path, the guard enforces the canon invariants (see WRITE PATH below).

**2. LOAD (the session-start read path) — SessionStart, non-blocking**

`session_context_loader.sh` fires on every session start. It detects the active desk from `cwd`; injects
the matching desk canon branch (or root canon for root sessions) into session context. This is the mechanism
that makes canon "always-on" — every session opens with the canon floor already in context.

**3. ON-DEMAND READ — skill invocation, honor-system**

The `/read` skill's Step 0.6 lazy-canon walk loads canon most-specific-first on demand. Because
`session_context_loader.sh` already loaded the desk floor, `/read` skips the floor to avoid double-stuffing.
`/canon-audit` does a deep seven-dimension read of the entire desk canon tree; it is read-only.
